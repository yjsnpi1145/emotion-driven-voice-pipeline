# WebUI 全站视觉系统与体验优化设计

日期：2026-08-29
状态：待用户评审
范围：普通配音工作台、导演模式、模型管理、LLM 设置、系统状态、逐句调整弹窗

## 1. 背景

当前 WebUI 已具备完整的章节配音、多角色导演、模型管理、LLM 配置和系统诊断能力。随着功能增加，界面出现了以下一致性问题：

- 顶部状态、页面导航和内容面板的视觉权重接近，主次不够明确；
- 小字号、紧凑控件和较多边框叠加后，长时间工作时扫描成本偏高；
- 普通工作台、导演模式和设置页的标题、按钮、状态徽标与空状态缺少统一规格；
- 页签使用字符作为图标，风格和语义不统一；
- 现有响应式规则能够降为单栏，但中等宽度下的工具栏、动作区和长表单仍可进一步优化；
- 已有键盘焦点和 reduced-motion 基础，但还需要处理粘性导航遮挡、触控尺寸和全站一致性。

本次采用中等强度优化：保留现有暗色控制台定位、信息架构、业务流程和状态机，通过统一设计令牌、组件状态、局部结构和响应式规则提升整体体验。

## 2. 目标

1. 建立一套覆盖全站的暗色专业工具视觉系统。
2. 明确页面、面板、分组、字段和动作之间的视觉层级。
3. 在不降低桌面信息密度的前提下，提高文字、状态和主要操作的可扫描性。
4. 让所有页面在 375、768、1024 和 1440 像素宽度下保持可用且无横向溢出。
5. 统一键盘焦点、悬停、禁用、忙碌、选中、成功、提醒和危险状态。
6. 不引入 Node 构建链、外部 CDN、图标包或新的运行时依赖。

## 3. 非目标与不可变约束

- 不重写 FastAPI 原生 SPA，不迁移 React、Vue、Tailwind 或组件框架。
- 不改变 API、持久化格式、任务状态机、SSE 生命周期或现有并发保护。
- 不改变任何工作流步骤、表单字段含义、默认值、按钮触发条件或权限边界。
- 不改变原文、角色、译文、中文参考文本或任何用户内容。
- 全局表演指导仍只能影响情绪向量、语速和停顿。
- 不删除历史部分成功项目所需的重新拼接、局部重生成和按句导出入口。
- 不读取或在 DOM 中新增真实 API Key、运行时隐私数据、文章全文、音频内容或模型权重信息。

## 4. 设计方向

### 4.1 风格

采用“专业音频制作控制台”方向：克制、清晰、数据密集但可读。保留深色界面与现有蓝色品牌识别，减少装饰性阴影和不必要的颜色竞争。

- 主色只用于当前导航、焦点、主按钮和关键进度；
- 成功、提醒、危险颜色只表达语义状态；
- 表面层级通过背景明度、边框和极轻阴影区分；
- 动效限于 150–200ms 的状态反馈，不使用持续装饰动画；
- 系统字体栈优先，不请求远程字体。

### 4.2 设计令牌

在 `styles.css` 的 `:root` 中整理并补齐以下令牌族：

- 表面：`--surface-canvas`、`--surface-panel`、`--surface-subtle`、`--surface-raised`；
- 文本：`--text-primary`、`--text-secondary`、`--text-tertiary`；
- 语义色：`--interactive`、`--success`、`--warning`、`--danger` 及对应柔和背景；
- 边框：默认、强调、交互和焦点；
- 间距：4、8、12、16、20、24、32 像素；
- 字号：12、14、16、20、28 像素；
- 圆角：6、8、10 像素和胶囊状态；
- 控件高度：紧凑 36px、默认 40px、关键触控目标 44px；
- 阴影与过渡：面板轻阴影、浮层阴影、快速状态过渡。

保留旧变量作为兼容别名，避免一次性破坏已有动态类名和页面局部样式。

## 5. 全局框架

### 5.1 顶部栏

- 保留品牌、服务状态、活动模型、ASR 开关、刷新和关闭服务入口；
- 品牌区与状态操作区使用更明确的间距和分组；
- 状态徽标降低视觉重量，危险操作保持明确但不持续抢占注意力；
- 刷新按钮改用内联 SVG，并保留可访问名称与原有事件绑定；
- 小屏允许状态区换行，隐藏内容必须仍能在系统状态页查看。

### 5.2 主导航

- 保留五个现有页签及其 `data-view`、`aria-selected` 和切换逻辑；
- 字符图标替换为同一笔画体系的内联 SVG，装饰图标使用 `aria-hidden="true"`；
- 当前页签同时使用文字、颜色和底部/侧边指示，不只依赖颜色；
- 导航继续粘性定位，并为页面设置对应的 `scroll-padding-top`，防止键盘焦点被遮挡。

### 5.3 内容画布

- 全站保持可利用完整宽度，避免给生产工具增加不必要的窄版心；
- 统一页面标题、面板标题、辅助说明、动作区和状态区间距；
- 面板阴影更轻，嵌套区域主要依靠表面色和边框区分；
- 空状态、加载状态和错误状态使用统一结构和语义。

## 6. 组件系统

### 6.1 按钮

- 统一主按钮、次按钮、危险按钮、图标按钮和字段附属按钮的高度、圆角和字体；
- 主按钮每个动作组原则上只保留一个最高视觉权重；
- 所有可点击控件提供 hover、active、focus-visible、disabled 和 busy 反馈；
- 图标按钮至少 40×40px，并通过 `aria-label` 或可见文字命名。

### 6.2 表单

- 标签、帮助文本、错误文本和输入控件建立固定的垂直节奏；
- 输入框、文本域和下拉框统一边框、焦点、禁用和只读状态；
- 两列或多列字段在中窄屏按语义顺序降为单列；
- 不修改字段名称、验证规则、默认值和提交行为。

### 6.3 状态与反馈

- 状态徽标统一为中性色默认、蓝色进行中、绿色完成、黄色待处理、红色失败；
- 徽标文本保持现有业务语义，不仅用颜色表达状态；
- toast 使用统一宽度、边框和入场反馈；reduced-motion 下禁用位移动画；
- 错误信息继续保持路径脱敏，并提供既有恢复操作。

### 6.4 列表与选择

- 章节、分块、导演项目、语句、角色预设和模型卡使用一致的悬停、选中和禁用语言；
- 选中态同时使用边框、背景和明确标记，避免只靠低对比底色；
- 不改变虚拟列表高度计算、选择 token、拖放或局部编辑状态。

### 6.5 弹窗

- 逐句调整弹窗统一标题栏、上下文区、字段区、音频区、操作状态和底部动作层级；
- 保持原有 dialog 生命周期、字段联动、reference/GSV 重生成及关闭行为；
- 窄屏使用接近全屏的安全边距，底部动作按主次顺序排列；
- 键盘焦点在弹窗内清晰可见，关闭后仍由既有逻辑恢复。

## 7. 页面级优化

### 7.1 普通配音工作台

- 章节摘要强化为紧凑指标组，整篇音频与主要动作形成独立动作区；
- 三栏布局继续保留“章节 / 分块 / 编辑器”工作模型；
- 分块筛选、选中态、编辑表单和音频版本区使用统一组件规格；
- 在 1220px 以下转为两栏加底部编辑器，在 820px 以下转为单栏。

### 7.2 导演模式

- 保留“项目 / 导演工作区 / 角色预设”结构，强化阶段轨道、角色区和语句时间线层级；
- 全局表演指导、预处理复核和 LLM 活动区使用一致的可折叠面板语言；
- 时间线工具栏在窄屏自动换行，筛选与选择操作不发生横向溢出；
- 所有角色映射、跳过、拖放、翻译编辑和逐句调整行为保持不变。

### 7.3 模型、LLM 与系统页

- 设置页使用一致的页面标题、表单面板和辅助说明；
- 模型卡突出名称、可用状态和当前激活状态，次级路径信息降低视觉权重；
- LLM 表单继续禁止密钥回显，测试和保存动作保持独立 busy 状态；
- 系统页清晰区分 ready、busy、stopped_expected 和错误，不把按需停止显示为故障。

## 8. 响应式与可访问性

- 验收宽度：375、768、1024、1440px；页面与主要工具栏不得产生非预期水平滚动；
- 正文与控件文字以 14px 为主，小型元信息不得低于 12px；
- 普通文本对背景目标对比度至少 4.5:1；
- 所有交互元素提供至少 2px 的高对比 `focus-visible` 指示；
- 粘性头部和导航不得完全遮挡获得焦点的控件；
- 保留正确标题顺序和现有 ARIA live/status 语义；
- `prefers-reduced-motion: reduce` 下关闭脉冲、扫光、toast 位移和非必要过渡；
- 375px 下高频操作目标优先达到 44px，桌面紧凑控件不低于 36px。

## 9. 实现边界

主要改动限定在：

- `src/voice_pipeline/webui/styles.css`
- `src/voice_pipeline/webui/index.html`
- 必要时对 `app.js`、`director.js` 中动态 HTML 模板增加纯展示类名或 SVG；不得改动业务分支和状态转换。

资源版本查询参数统一升级，避免真实服务重启后浏览器继续使用旧 CSS 或 JavaScript。

## 10. 测试与验收

### 10.1 自动化回归

- 为新的全局令牌、SVG 页签、可访问标签、响应式规则和 reduced-motion 规则添加静态契约测试；
- 运行现有 WebUI、Director JavaScript、API contract 和非 GPU 测试；
- 对修改过的 JavaScript 执行 `node --check`，对 Python 改动执行对应 lint/type 检查；
- 确认动态元素 ID、`data-view`、表单 name 和现有模块引用未改变。

### 10.2 浏览器验收

- 普通工作台、导演模式、模型管理、LLM 设置、系统状态均可切换；
- 关键按钮、开关、折叠区、筛选器和逐句调整弹窗状态正确；
- 375、768、1024、1440px 下检查可读性、换行和水平溢出；
- 使用键盘检查页签、表单、列表、按钮和弹窗焦点；
- 浏览器控制台无新增错误，健康状态仍为 real / migration 0009。

### 10.3 发布验收

修改 `src` 后必须：

1. 构建 wheel；
2. 强制安装到 `.venv-control`；
3. 重启真实服务；
4. 重新检查 `/api/v1/health` 与运行日志摘要；
5. 在真实服务页面完成浏览器验收。
