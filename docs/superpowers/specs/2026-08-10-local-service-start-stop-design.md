# 本地服务一键启动与关闭设计

## 目标

为 Windows 本地用户提供一个位于仓库根目录、可双击运行的 `启动服务.bat`，并在
WebUI 顶栏提供“关闭所有服务”按钮。两者必须复用现有控制面和引擎生命周期管理，不能
另行维护 IndexTTS2 或 GPT-SoVITS 进程。

## 启动行为

- `启动服务.bat` 只支持 Windows，并要求 PowerShell 7 的 `pwsh` 命令可用。
- BAT 从自身所在目录定位仓库，不依赖当前工作目录，也不包含开发者绝对路径。
- 默认使用 `config/app.example.yaml`、`.venv-control\Scripts\python.exe` 和
  `scripts/start.ps1` 启动真实模式。
- 启动前请求 `http://127.0.0.1:8765/api/v1/health`：
  - 若返回 HTTP 200 且 `status=ready`，不重复启动服务，只打开 WebUI；
  - 否则调用现有 `start.ps1`，由其等待控制面、存储、调度器和质量服务就绪。
- 启动成功后使用 Windows 默认浏览器打开 `http://127.0.0.1:8765/`。
- `pwsh`、配置、控制环境缺失或启动失败时，BAT 显示中文错误，保留窗口供用户查看，
  返回非零退出码，并且不打开浏览器。

## 关闭行为

- 顶栏状态区新增危险操作按钮 `关闭所有服务`。
- 用户点击后，浏览器必须先显示明确确认框，说明正在执行的生成任务会被中断。
- 用户取消时不发送请求，也不改变页面状态。
- 用户确认后按钮进入禁用的“正在关闭…”状态，并请求
  `POST /api/v1/control/shutdown`。
- 复用现有 `ControlPlane.shutdown()`：停止接收任务、终止或中断当前任务、关闭
  IndexTTS2 和 GPT-SoVITS 受管进程、停止控制面，最终使 WebUI 后端退出。
- 收到 `{"status":"shutting_down"}` 后，页面立即进入终止态：停止章节刷新和 LLM
  活动轮询，禁用所有按钮和表单控件，显示全屏提示“所有服务已关闭，可以关闭此页面”。
- 若关闭请求在服务退出过程中表现为连接中断，也视为预期结果并进入终止态；只有在
  服务仍可访问且返回明确 HTTP 错误时才恢复按钮并显示错误。
- 普通网页不能可靠关闭由用户打开的浏览器标签页，因此终止态页面保留在标签页中，
  但所有后端和模型服务均已退出。

## 文件边界

- `启动服务.bat`：启动前检查、调用 `scripts/start.ps1`、打开浏览器。
- `src/voice_pipeline/webui/service-shutdown.js`：可独立测试的确认和关闭请求协调逻辑。
- `src/voice_pipeline/webui/index.html`：顶栏按钮与终止态遮罩结构。
- `src/voice_pipeline/webui/app.js`：接入按钮、停止轮询、进入终止态。
- `src/voice_pipeline/webui/styles.css`：危险按钮与终止态遮罩视觉。
- 现有 `/api/v1/control/shutdown` 和后端生命周期保持不变。

## 验收

1. 从仓库以外的当前目录调用 BAT，仍能正确定位并启动仓库。
2. 服务已运行时再次调用 BAT，不产生第二个控制进程，只打开 WebUI。
3. BAT 的配置或 `pwsh` 前置条件不满足时返回非零且不打开浏览器。
4. 取消 WebUI 确认框不会发送关闭请求。
5. 确认后只发送一次关闭请求，并进入不可继续操作的终止态。
6. 真实进程测试验证关闭后 8765、9871、9880 不再监听，记录的控制面和模型 PID 均退出。
7. 前端模块语法、Ruff、Mypy 和非 GPU 测试全部通过。
