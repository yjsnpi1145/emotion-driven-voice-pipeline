# 工作台当前任务选择持久化设计

## 目标

刷新 WebUI 后恢复用户最后查看的章节任务和分块，并立即从服务端重新加载真实任务状态、版本指针、进度与事件流。

## 根因

任务、分块、版本和运行状态已经持久化在 SQLite 中。丢失的是 `app.js` 内存中的 `state.run` 与 `state.selected`：页面初始化时固定选择章节列表第一项和该章节第一段，因此用户最后查看的任务/分块无法恢复。

## 方案

增加独立纯函数模块 `selection-state.js`，在浏览器 `localStorage` 中只保存：

- `schema_version: 1`
- `run_id`
- `segment_id`

不保存标题、文案、情绪向量、音频路径、任务状态或 API 密钥。刷新后仍以 SQLite/API 返回的数据为唯一事实来源。

初始化顺序：

1. 并行加载章节列表、模型、系统状态和本地路径。
2. 读取本地选择指针。
3. 若保存的 `run_id` 仍在章节列表中，恢复它及其中仍存在的 `segment_id`。
4. 保存的任务不存在时，优先选择最近的 `queued/running` 任务，其次选择最新任务。
5. 没有任务时清除选择指针并渲染空状态。
6. `selectRun()` 完成 API 数据加载后才写入指针，并按原逻辑连接 SSE。
7. `selectSegment()` 完成历史加载后更新分块指针。

## 容错

- JSON 损坏、schema 不支持、ID 格式非法：忽略并按默认规则选择。
- `localStorage` 被浏览器禁用或抛出安全/配额异常：静默退化为当前内存行为，不阻断工作台。
- 保存的章节或分块已删除：回退到有效任务/第一分块，并覆盖失效指针。
- 删除当前章节：先清除指针，再由下一个有效章节建立新指针；无剩余章节则保持清空。
- 刷新时有运行中任务：重新请求 progress，并重新建立 SSE，不从本地伪造状态。

## 非目标

- 不持久化未保存的编辑器草稿、搜索条件、滚动位置或导航页签。
- 不改变数据库和 REST API。
- 不保证在 LLM POST 尚未返回 `run_id` 时刷新后找回该尚未建立的章节；一旦服务端返回 `202`，选择即可持久化。

## 验收

1. 选择非列表第一项的章节后刷新，仍打开该章节。
2. 选择非第一分块后刷新，仍打开该分块。
3. 运行中任务刷新后继续显示真实进度并接收事件更新。
4. 保存的章节/分块已不存在时安全回退。
5. 损坏或不可用的浏览器存储不导致白屏或初始化失败。
6. 既有 WebUI、章节、任务和版本回归测试全部通过。
