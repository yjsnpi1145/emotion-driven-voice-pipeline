# 多角色导演模式设计

日期：2026-08-14
状态：已通过产品设计评审

## 1. 目标

在现有单角色整篇配音、分块版本管理和局部重生成能力之上，增加一个独立的“导演模式”。用户可以导入文章或剧本，由 LLM 识别需要配音的语句、旁白、舞台说明、角色及角色别名；用户完成角色校对、翻译校对和角色音色映射后，系统才开始调用 IndexTTS2 与 GPT-SoVITS。

第一版必须满足：

- LLM 分析与 GPU 推理解耦；分析完成后不得自动开始配音。
- 默认识别旁白，并提供“配音旁白”总开关。
- 用户可以通过时间线拖拽、多选和下拉框修正语句角色。
- 支持拆分语句、合并相邻语句、配音/不配音切换。
- 角色别名可自动归并，并支持人工重命名、合并和拆分。
- 角色预设可跨剧本复用，并只保存模型实际使用的参数。
- 跨语言项目在 GPU 推理前提供目标语言文本预览与编辑。
- 低置信度角色判断必须经过人工确认。
- 单句失败不能阻止其他语句继续生成。
- 所有源文、LLM 判断、人工修订和生成快照均可审计、可恢复。

## 2. 非目标

第一版不实现：

- 多人同时说话或音轨重叠；
- 背景音乐、音效生成或自动混音；
- 自动口型同步；
- 根据年龄、性格或声线描述自动选择音色；
- 未经用户确认自动开始 GPU 生成；
- 多用户协作、公网部署或分布式调度。

年龄、声线和表演风格等自由文本不进入角色预设，因为 IndexTTS2 与 GPT-SoVITS 不消费这些字段，界面不得暗示模型会响应它们。

## 3. 与现有系统的关系

导演模式使用新的持久化项目和编排服务，不改变现有“新建整篇配音”入口的请求、状态或行为。

复用现有能力：

- OpenAI 兼容 LLM 设置和实时活动日志；
- IndexTTS2 情绪参考生成；
- GPT-SoVITS 模型档案、权重校验与模型切换；
- 单 GPU 串行队列和受管模型进程；
- 不可变音频 artifact、版本、缓存和质量检查；
- 分块参考/GSV局部重生成；
- 整篇拼接、导出、任务恢复与历史管理。

现有 `ChapterSynthesisRequest` 冻结一套 `base_voice_path + model_profile_id`，不适合多角色。导演模式必须在自己的项目层保存角色映射，并在开始生成时为每个语句冻结对应角色预设；不得把可变角色映射临时塞入旧章节请求。

## 4. 总体架构

### 4.1 ScriptAnalysisService

负责本地预切分、分块 LLM 分析、原文范围验证和全局角色归并。不调用任何 GPU 引擎。

### 4.2 DirectorProjectStore

使用 SQLite 保存导演项目、分析块、角色、语句、翻译结果、修订号、编辑事件和生成映射。SQLite 是唯一事实来源，SSE 只发送变化通知。

### 4.3 RolePresetService

管理可跨项目复用的精简角色预设。基础参考音频导入本地托管目录，GPT-SoVITS 使用现有模型档案。

### 4.4 DirectorGenerationService

验证项目已通过全部人工确认，创建不可变生成快照，将有效语句物化为现有持久化分块、参考任务、GSV任务和音频版本，并负责容错调度与最终拼接。

### 4.5 WebUI

增加一级“导演模式”页签，采用可恢复的分阶段工作流和“时间线 + 角色投放区”主编辑界面。

## 5. 项目状态机

项目状态固定为：

```text
draft
  -> analyzing
  -> role_review
  -> translating
  -> translation_review
  -> voice_mapping
  -> ready
  -> generating
  -> generation_incomplete | succeeded
```

状态说明：

- `draft`：原文尚可编辑。
- `analyzing`：执行本地预切分、LLM分块分析和角色归并。
- `role_review`：用户修订角色、别名、语句边界和配音状态。
- `translating`：按已确认语句批量生成目标文本、中文参考文本和参数。
- `translation_review`：用户校对翻译与参考文本。
- `voice_mapping`：为所有有效角色配置角色预设。
- `ready`：全部生成前校验通过。
- `generating`：不可变快照已创建，GPU任务正在运行。
- `generation_incomplete`：至少一个有效语句失败，但其他语句已继续执行。
- `succeeded`：所有有效语句就绪且第一版整篇音频已拼接。

服务端强制状态转换，前端隐藏按钮不能替代后端校验。

## 6. 数据模型

### 6.1 director_projects

至少保存：

- `project_id`、标题、创建和更新时间；
- 原文、原文 SHA-256、原文语言、目标语言；
- `narration_enabled`；
- 当前状态；
- 分析、角色、翻译、音色映射和生成修订号；
- 当前生成执行 ID、最终音频和时间线；
- 最近错误和软删除时间。

原文进入 `analyzing` 后不可就地覆盖。用户修改原文必须创建新的分析修订，并使角色、翻译、映射确认及待生成快照失效。

### 6.2 director_analysis_chunks

保存分析块的绝对字符范围、精确文本 SHA、LLM 配置指纹、Prompt/Schema版本、状态、尝试次数和已验证结果。成功块可复用，失败块可独立重试。

### 6.3 director_roles

至少保存：

- 稳定 `role_id` 和项目 ID；
- 标准角色名；
- 类型 `narrator | character | unknown`；
- 别名集合；
- LLM置信度；
- 是否人工确认；
- 当前角色预设 ID；
- 修订号。

“旁白”是系统内置角色。角色只有在无语句引用时才能直接删除；其他情况必须先改派、合并或将语句设为不配音。

### 6.4 director_utterances

至少保存：

- 稳定 `utterance_id`、项目 ID 和原始顺序；
- `source_start`、`source_end` 和精确原文切片；
- 类型 `dialogue | narration | stage_direction`；
- `speak_enabled`；
- 当前角色 ID、角色置信度和人工确认状态；
- 目标语言配音文本；
- 中文情绪参考文本；
- 8维情绪向量、语速、句后停顿和种子；
- 分析、角色和翻译修订号；
- 生成后的 task、segment、reference version 和 GSV version 关联。

所有语句及不配音区间必须无重叠、无缺失地覆盖完整原文。只能在合法字符边界拆分；只能合并原文中相邻的语句；不得任意重排。源文不可在角色复核页自由改写，目标语言文本和中文参考文本可以编辑。

### 6.5 role_presets

角色预设只保存有效推理输入：

- 预设名称；
- 托管基础参考音频的相对路径、内容 SHA-256 和音频元数据；
- GPT-SoVITS模型档案 ID；
- 默认语速；
- 状态、创建和更新时间。

导入时将基础参考音频复制到本地角色库并原子发布，不能只保存用户外部路径。基础参考音频是 IndexTTS2 音色克隆输入，不施加 GPT-SoVITS 的 3--10 秒参考窗口。

### 6.6 director_edit_events

使用追加式事件记录：

- 拆分、合并和配音状态切换；
- 语句角色改派；
- 角色重命名、合并、拆分和新建；
- 低置信度确认；
- 译文、中文参考文本和有效参数修改；
- 角色预设映射变更；
- 操作类型、对象 ID、操作前后修订号、时间和结构化差异摘要。

事件用于审计和问题诊断，不作为重放数据库的唯一来源。

## 7. LLM分析与翻译契约

### 7.1 本地预切分

按章节、场景标题、空行、段落、标点安全边界和上下文预算进行确定性预切分。每块保存绝对字符范围和稳定 `block_id`，原文不得规范化后再计算位置。

### 7.2 分块分析

每个块的结构化结果包含源文子范围、语句类型、临时角色名、别名、角色置信度和建议配音状态。服务端重新验证每个范围的精确切片、覆盖、顺序和边界。

LLM 返回字符缺失、重叠、越界或改写文本时，仅将该块判为失败并按既有重试策略修复；不能接受近似匹配后静默发布。

### 7.3 全局角色归并

汇总各块的临时角色和别名，通过只包含角色摘要的轻量请求生成标准角色。高置信度别名可以自动归并；不确定的归并保持独立并标记待复核。用户可在 UI 中重命名、合并或拆分。

### 7.4 低置信度规则

LLM仍返回最可能角色，但将低置信度语句标记为待复核。所有待复核项必须由用户确认或改派后才能进入翻译阶段。人工确认写入修订和编辑事件，迟到的 LLM 结果不得覆盖。

### 7.5 翻译与参数规划

只对最终 `speak_enabled=true` 的语句分批请求。每项携带稳定 `utterance_id + revision`，结果包含：

- 目标语言配音文本；
- 中文参考文本；
- 8维情绪向量；
- 语速；
- 句后停顿。

目标语言与原文相同时，配音文本默认保留原文切片；中文参考文本仍按现有跨语言规则生成。所有情绪向量继续使用现有共享 Schema 校验，不允许通过数值归一化偷偷修改 LLM 输出。

### 7.6 可恢复性和并发

分析块和翻译批次分别保存输入 SHA、LLM 配置指纹、Prompt/Schema版本、状态、尝试次数和验证结果。成功批次在输入及指纹未变化时不重复请求。默认 LLM 并发为2，并在设置中允许调整为1至有限上限。

## 8. WebUI交互

### 8.1 导入

用户输入标题、原文、原文语言或自动检测、目标语言及旁白开关。点击“分析剧本”后返回可跟踪任务，复用 LLM 实时活动窗口；GPU保持空闲。

### 8.2 角色与语句复核

主视图采用“时间线 + 角色投放区”：

- 左侧固定角色列表，显示别名、语句数量和待复核数量；
- 中间按原文顺序展示全部语句；
- 旁白、对白、舞台说明和不配音内容使用可区分样式；
- 将角色拖到单句或多选语句上完成改派；
- 始终提供下拉框和批量操作作为非拖拽替代；
- 支持低置信度、未确认、旁白和不配音筛选；
- 支持光标拆分、合并相邻语句、配音状态切换；
- 支持角色重命名、合并、拆分和新建。

关闭旁白时，旁白语句保留并变为不配音；重新开启可以恢复其配音资格，但仍需通过角色映射校验。

### 8.3 翻译预览

逐句展示原文、目标语言配音文本、中文参考文本、情绪向量、语速和停顿。用户可以编辑目标文本和中文参考文本。编辑只递增相关语句修订，不重新分析整篇。

### 8.4 角色音色映射

角色表允许选择已有预设或新建预设，播放基础参考音频，选择 GPT-SoVITS模型档案并设置默认语速。关闭旁白时不要求旁白预设；没有有效配音语句的角色也不阻挡生成。

### 8.5 生成与修复

开始前展示所有阻断项。生成中仍按原文顺序展示每句的等待、参考生成、GSV合成、完成和失败状态。失败项支持单独或批量重试，其他语句继续运行。刷新和服务重启后从 SQLite 恢复页面。

## 9. API边界

导演模式接口统一放在 `/api/v1` 下：

```text
POST   /api/v1/director-projects
GET    /api/v1/director-projects
GET    /api/v1/director-projects/{project_id}
DELETE /api/v1/director-projects/{project_id}
POST   /api/v1/director-projects/{project_id}/analyze
GET    /api/v1/director-projects/{project_id}/roles
GET    /api/v1/director-projects/{project_id}/utterances

PATCH  /api/v1/director-roles/{role_id}
POST   /api/v1/director-roles/merge
POST   /api/v1/director-roles/{role_id}/split
PATCH  /api/v1/director-utterances/{utterance_id}
POST   /api/v1/director-utterances/{utterance_id}/split
POST   /api/v1/director-utterances/merge

POST   /api/v1/director-projects/{project_id}/confirm-roles
POST   /api/v1/director-projects/{project_id}/translate
POST   /api/v1/director-projects/{project_id}/confirm-translation
POST   /api/v1/director-projects/{project_id}/start-generation
POST   /api/v1/director-projects/{project_id}/resume
GET    /api/v1/director-projects/{project_id}/progress
GET    /api/v1/director-projects/{project_id}/events
```

角色预设提供独立 CRUD、参考音频导入、播放和完整性诊断接口。

所有修改接口携带 `expected_revision`。拖拽批量改派、角色合并和语句合并必须在单个事务中提交。旧页面提交返回版本冲突，不能覆盖新数据。

开始生成接口必须幂等；重复提交相同项目修订返回已有生成执行，不能重复创建任务。

## 10. 生成快照与调度

### 10.1 生成快照

点击开始时冻结：

- 项目和语句修订；
- 配音状态、角色和原始顺序；
- 目标文本、中文参考文本和情绪向量；
- 角色预设、基础参考音频 SHA；
- GPT/SoVITS 权重 SHA 和引擎指纹；
- 语速、停顿、输出规格和种子。

生成开始后的编辑形成新草稿并使相关当前结果标记为待更新，不能修改正在执行的快照。

### 10.2 两阶段 GPU 调度

独占进程环境下先运行所有 IndexTTS2 参考任务，再切换到 GPT-SoVITS。GSV阶段按模型档案分组，同一模型的语句连续执行，减少权重和进程切换。每个输出仍绑定原始 ordinal，最终按剧本顺序拼接。

WebUI展示原文顺序，不把后台分组顺序当作产品顺序。

### 10.3 故障隔离

- 单句失败只标记该句并继续。
- 某个模型加载失败时，将该模型的未执行语句标记为同一角色级错误，继续其他模型。
- 服务重启后恢复未完成执行；已成功版本和缓存不得重复生成。
- 超时继续遵循现有受管进程终止确认和 GPU 互斥契约。
- 所有有效配音语句就绪前不能拼接整篇。

### 10.4 拼接

旁白关闭、舞台说明和其他不配音内容不产生音频。有效语句按原始顺序和已确认停顿拼接。首次全部就绪时自动生成第一版整篇音频；局部重生成后仍由用户显式重新拼接。

## 11. 服务端校验

以下情况必须拒绝继续：

- 原文覆盖不完整、重叠、越界或顺序变化；
- 存在未确认的低置信度语句；
- 翻译修订落后于角色或语句修订；
- 有效角色未绑定角色预设；
- 基础参考音频、模型文件缺失或哈希不一致；
- 情绪向量、语速、停顿或文本不符合共享 Schema；
- 项目状态不允许当前命令；
- `expected_revision` 已过期；
- 生成快照与当前已确认修订不一致。

## 12. 验收标准

### 12.1 原文与 LLM

- 中英日混合剧本保持精确字符覆盖。
- 嵌入叙述的对白可拆成旁白与角色台词。
- 非法范围结果被拒绝并仅重试失败块。
- 长文本中断后成功块不重复调用。
- 跨章节别名可归并，不确定项进入人工复核。
- 未确认低置信度项时不能翻译。

### 12.2 编辑与并发

- 拆分后的区间精确组成原区间。
- 只能合并相邻语句且顺序不变。
- 单句、多选拖拽和下拉改派结果一致。
- 关闭旁白不删除任何源文。
- 旧修订不能覆盖新修订。
- 迟到 LLM 结果不能覆盖人工修改。

### 12.3 角色预设

- 参考音频导入、原子发布和 SHA 校验正确。
- 一个预设可分配给多个角色。
- 缺失或损坏音频及模型时禁止生成。
- 生成快照不受后续预设修改影响。
- 不同角色输入和模型不能错误共享缓存。

### 12.4 生成与恢复

- 所有 Index 参考任务先于 GSV 阶段。
- GSV按模型档案分组，GPU最大并发始终为1。
- 单句或单模型失败不停止其他可执行语句。
- 重启后已完成结果不重复推理。
- 有效语句缺失时不能最终拼接。
- 最终时间线严格遵循原文顺序。

### 12.5 WebUI

- 刷新和重启后恢复当前项目、阶段和选择。
- 拖拽及非拖拽角色修改均可用。
- 低置信度筛选、拆分、合并和旁白开关有效。
- 翻译预览可编辑并产生新修订。
- 进度、失败状态和阻断项与 SQLite 一致。
- `generation_incomplete` 项目修复后可以继续执行并完成。

## 13. 可行性结论

该功能有条件高可行。现有系统已经具备约三分之二的底层能力，新增工作主要集中在导演项目持久化、角色/预设实体、分阶段 LLM 协议、多角色调度和 WebUI 工作流。核心技术风险不是 TTS 模型能力，而是 LLM 说话人判断的不确定性、长文本结构化输出可靠性和多模型切换成本；本设计分别通过强制人工复核、分块可恢复分析和阶段化分组调度控制这些风险。

实现应拆成多个可独立验收的批次，不应一次性同时修改 LLM、存储、调度和完整 WebUI。
