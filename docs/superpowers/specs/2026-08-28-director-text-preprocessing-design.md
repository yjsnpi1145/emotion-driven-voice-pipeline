# 导演模式文本预处理层设计

## 目标

在导演模式的原文导入与剧本分析之间增加一个独立、可审阅的“配音文本预处理”阶段。该阶段负责消除不同作者在引号、标点、换行和对白组织上的差异，避免纯标点分块、对白与插入叙述混合、引号跨 LLM 大块边界等问题。

预处理提供两种模式：

1. **结构清洗（默认）**：只调整结构、空白和标点，不修改正文措辞。
2. **配音改写**：先执行结构清洗，再由 LLM 逐段进行不增、不减、不改变剧情信息的等义改写。

两种模式都保持每段原有语言。目标语言翻译仍由后续翻译阶段负责。

## 非目标

- 不在预处理阶段分配角色或选择音色。
- 不把混合语言统一成目标语言。
- 不允许 LLM 删除、增加或改变剧情信息。
- 不覆盖或修改用户导入的原始文本。
- 不自动迁移旧导演项目。

## 流程与状态

新项目流程为：

```text
导入原文
  -> 选择预处理模式
  -> preprocessing
  -> preprocess_review
  -> 用户确认预处理稿
  -> analyzing
  -> role_review
  -> translating
  -> translation_review
  -> voice_mapping
  -> ready / generating
```

新增状态：

- `preprocessing`：本地清洗或逐段 LLM 改写正在运行。
- `preprocess_review`：结果已经持久化，等待用户校对和确认。

只有用户明确确认预处理稿后才能启动剧本与角色分析。未保存草稿、空段落、结构校验失败或后台任务仍在运行时禁止确认。

## 文本与审计数据

项目永久保留三层文本：

1. `source_text`：用户导入的只读原文及其 SHA-256。
2. `structural_text`：本地结构清洗得到的稳定基线。
3. `preprocessed_text`：当前可编辑、最终供分析使用的预处理稿。

预处理稿按段落持久化。每段记录：

- 稳定段落 ID 和顺序；
- 原文范围及原文；
- 本地结构清洗稿；
- 当前预处理稿；
- 模式、处理状态和校验结果；
- 段落修订号；
- 是否经过 LLM、自动回退或用户编辑；
- 输入和输出指纹。

原文与预处理稿均可独立审计。后续分析只读取已经确认的 `preprocessed_text`，不再使用原文偏移量。后续语句偏移量属于预处理稿自身，并保留到原始段落 ID 的追踪关系。

## 本地结构清洗

结构清洗器必须先扫描整篇文本，再决定 LLM 请求块，不能先按固定字符数切开。它维护跨段落的引号状态，并识别：

- `quoted_dialogue`：成对引号内的对白；
- `quote_bridge_narration`：两段对白之间的插入叙述；
- `narration`：普通叙述；
- `formatting`：空白和仅承担排版作用的标点；
- `pause_marker`：只有省略号或类似停顿符号、没有可发音文字的内容。

本地清洗执行以下确定性处理：

- 将 CRLF 等换行统一为 LF，并折叠多余空行；
- 统一中文省略号和连续英文句点的表示；
- 跨整篇文章匹配中文、日文和 ASCII 成对引号；
- 禁止在已匹配引号内部建立 LLM 大块边界；
- 将孤立的结束引号、逗号、句号和纯换行并入相邻的语义单元；
- 将只有停顿符号的单元转换成 `pause_marker`，不作为 TTS 语句；
- 保留文字、数字、专有名词和外语片段；
- 保证结构清洗输出非空、顺序稳定且可重放。

示例：

```text
“我的初吻……”她慌乱地摆弄着手指，目光四处乱飘，“祥子，为什么——”
```

必须稳定得到：

```text
[quoted_dialogue] “我的初吻……”
[quote_bridge_narration] 她慌乱地摆弄着手指，目光四处乱飘，
[quoted_dialogue] “祥子，为什么——”
```

## 配音改写

配音改写以本地结构单元为输入，不能把整篇文本作为自由改写任务交给 LLM。每个请求携带稳定的段落 ID、单元 ID、结构上下文和原文。

LLM 响应必须：

- 原样返回每个单元 ID；
- 不遗漏、重复、新增或重新排序单元；
- 不把对白与插入叙述合并；
- 保持单元原有语言；
- 保留数字、人名、外语词汇和关键专有名词；
- 只调整措辞、语序和朗读可读性；
- 为每个输出提供输入句子覆盖映射，使每个输入句子 ID 恰好出现一次。

本地校验包括：

- 单元 ID 和顺序完全一致；
- 输入句子覆盖集合完全一致且无重复；
- 数字及受保护词项未丢失；
- 对白和叙述上下文未改变；
- 输出非空且长度变化处于合理范围；
- 未发生非预期语言转换。

单段校验失败时仅将该段回退到本地结构清洗稿，并记录具体错误；其他成功段落继续保留。LLM 请求或 Schema 校验失败时，用户可以重试，也可以使用本地结构清洗稿继续。

## WebUI

项目导入区增加预处理模式：

- `结构清洗（默认）`
- `配音改写`
- `跳过预处理（兼容/调试）`

跳过预处理需要显示可能出现异常分块的提示。主按钮改为“创建并开始预处理”。

`preprocess_review` 页面按段落懒加载双栏校对：

- 左栏显示只读原文；
- 右栏显示可编辑的预处理稿；
- 每段显示本地清洗、LLM 已改写、自动回退、用户已编辑或校验失败状态；
- 支持恢复原文、恢复本地清洗稿、重新改写该段、保存手动修改和查看差异。

页面顶部显示预处理阶段进度、LLM 实时输出、字数变化、改写段数、自动回退段数和未保存修改数。刷新后恢复当前项目、段落、滚动位置、未提交草稿和任务状态。

最终按钮为“确认预处理稿并开始角色分析”。

## API 与组件边界

新增独立组件：

- `StructuralTextCleaner`：无网络依赖的确定性全篇结构清洗；
- `PreprocessingService`：任务编排、缓存、段落回退和确认；
- `PreprocessingStore`：预处理运行、段落、修订和事件持久化；
- LLM 预处理客户端：逐段等义改写及 Schema 校验；
- 预处理验证器：覆盖映射、受保护词项、语言和结构检查。

API 至少覆盖：

- 启动或恢复项目预处理；
- 查询预处理进度和段落；
- 修改单段预处理稿；
- 恢复原文或本地清洗稿；
- 重试单段 LLM 改写；
- 确认预处理稿并启动分析。

组件之间通过结构化模型传递数据，分析服务只接收已确认的预处理稿，不直接依赖预处理内部表结构。

## 并发、恢复与错误处理

- 每个项目同一时间只允许一个预处理、分析或翻译命令运行。
- 重复提交返回已有命令状态，不创建新的 LLM 请求。
- 任一批次失败后取消同轮尚未开始的请求。
- 重试只请求输入指纹变化或尚未成功的段落。
- 服务重启后未完成命令标记为可恢复，不自动重复调用 LLM。
- 本地清洗失败时停留在预处理阶段；LLM 失败时允许使用本地稿继续。
- 翻译前再次拒绝纯空白、纯标点和纯引号的配音语句；停顿标记不会进入翻译 LLM。
- Schema 错误必须显示字段路径和对应段落或语句 ID。

## 旧项目处理

不实现旧项目转换或“创建新版副本”。用户已批准删除当前本地全部旧导演项目。删除在部署新预处理层前通过现有项目删除接口执行，先停止仍在运行的旧导演后台命令，再删除项目，避免旧请求继续消耗 LLM 配额。

公共产品逻辑不得在升级时自动删除其他用户的数据；本次删除只针对当前机器上已经获得用户明确授权的旧项目。

## 测试与验收

必须覆盖：

- 成对引号跨原 2400 字符边界；
- 对白、插入叙述、对白的确定性三段结构；
- 中文、日语、英语及混合语言引号；
- `……`、`......`、孤立结束引号、单句点和连续空行；
- 纯停顿单元不进入翻译或 TTS；
- 数字、专有名词和外语词项保留；
- LLM 遗漏、重复、乱序、擅自翻译或改变上下文；
- 单段失败回退和手动恢复；
- 重复点击不会产生并发 LLM 请求；
- 页面刷新和服务重启后的恢复；
- 未保存修改和失败段落阻止确认；
- 翻译请求不包含纯标点语句；
- 原文、清洗稿、预处理稿和审计事件均可恢复。

验收标准：不同写作风格的文章进入分析前均产生无纯标点配音项、引号结构稳定、可人工校对的预处理稿；用户确认后，现有导演分析、翻译和多角色生成流程继续工作。
