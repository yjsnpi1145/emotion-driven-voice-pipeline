# Director 短句情绪参考池设计

日期：2026-08-28  
状态：已通过会话设计评审，待实施计划

## 1. 背景

Director 模式中的单字、双字对白，例如“嗯”“诶”“啊”“砰”，无法稳定生成满足 GPT-SoVITS 约束的参考音频。现有流程让 LLM 扩写 `ref_text_cn`，再用 IndexTTS2 进行真实音频探测；实际运行中仍出现了以下失败：

- 扩写两次后参考音频只有 1.567 秒；
- 参考音频为 2.949 秒，距离 3 秒下限仅约 0.051 秒但仍被严格拒绝；
- 音频总长合格，但 Silero VAD 未识别到有效人声。

继续增加 LLM 修正次数不能从根本上保证时长和 VAD 稳定性，而且会增加 LLM 请求、IndexTTS2 推理次数与总耗时。

## 2. 目标

为极短对白提供一个按角色音色和情绪类别复用的中文参考音频池：

- 单字、双字对白不再依赖 LLM 扩写；
- 原始对白、目标语言配音文本、角色、速度、停顿、种子及原始连续情绪向量保持不变；
- 参考音频与交给 GPT-SoVITS 的中文 `prompt_text` 始终严格绑定；
- 不同角色或不同 IndexTTS2 音色不得串用参考；
- 缓存可跨页面刷新和服务重启复用；
- 单条缓存失败不得阻塞其他语句；
- 所有缓存选择、降级和重生成均可审计。

## 3. 非目标

- 不修改用户确认过的 `source_text` 或 `synthesis_text`；
- 不把连续 8 维情绪向量覆盖成离散类别；
- 不改变普通长度对白现有的 LLM 参考文本修正流程；
- 本阶段不提供用户自定义情绪模板编辑器；
- 不让一条缓存更新静默替换已经完成语句所绑定的历史参考版本。

## 4. 触发规则

系统对中文参考文本进行仅用于分类的规范化：删除首尾及内部空白、成对引号和 Unicode 标点符号，但不修改数据库中的原值。规范化后的“有效字符”包括 Unicode 字母、数字和中日韩表意字符，避免把“嗯，Your Majesty”误判为只有一个汉字的短句。

1. 规范化后包含 1～2 个有效字符时，直接进入情绪参考池，不调用 LLM 扩写或 IndexTTS2 时长探测循环。
2. 超过 2 个有效字符时，继续使用现有 `ReferenceTextDirector` 流程。
3. 普通流程达到两次修正预算后，若真实参考音频仍不在闭区间 3.0～10.0 秒内，自动回退到情绪参考池，而不是立即将语句标记为失败。
4. 空文本、纯标点或不包含可朗读文本的条目不伪装成短句；它们继续由输入校验或 Director 审核规则处理。

该规则只检查中文 `ref_text_cn`。目标语言可以是中文、日语、英语或其他已支持语言，`synthesis_text` 不参与短句池判定。

## 5. 情绪类别选择

参考池沿用产品现有 8 维向量顺序：

1. 愉悦
2. 愤怒
3. 悲伤
4. 恐惧
5. 厌恶
6. 忧郁
7. 惊讶
8. 平静

选择规则如下：

- 若“平静”为最高维度之一，选择平静；
- 仅当某个非平静维度的值不低于 `0.15`，且至少领先第二名 `0.05` 时，选择该非平静维度；
- 其他情况，包括全零、最高值过低、并列或差距不足，均选择平静；
- 原始连续向量保存在 Director utterance 中，不因分类而改变。

实现时将“明显主情绪”封装为独立、纯函数分类器，并用边界测试固定阈值，避免 UI 与后端各自实现不同规则。

## 6. 默认参考模板

每个模板都是自然简体中文，预期由正常语速生成 3～10 秒的普通话音频：

| 情绪 | `prompt_text` / IndexTTS2 文本 |
| --- | --- |
| 平静 | 我明白了，接下来就按照原定计划继续吧。 |
| 愉悦 | 听到这个消息，我心里真的感到非常高兴。 |
| 愤怒 | 这件事情让我无法继续保持冷静。 |
| 悲伤 | 想到已经发生的一切，我心里还是很难过。 |
| 恐惧 | 周围突然安静下来，让我感到有些害怕。 |
| 厌恶 | 这样的做法，实在让人感到难以接受。 |
| 忧郁 | 回想起从前的事情，心里难免有些惆怅。 |
| 惊讶 | 我完全没有想到，事情竟然会变成这样。 |

模板带有显式版本号。修改文字必须提升模板版本，使旧缓存继续可审计、新任务自动使用新键。

每个类别拥有固定的规范化 IndexTTS2 情绪向量。该向量只用于生成池音频；Director utterance 中用户审核过的原向量不变。单字目标的实际情绪由所选池音频传递给 GPT-SoVITS。

## 7. 缓存键与生命周期

池条目分为“不含种子的池族”和“包含种子的具体尝试”。池族逻辑键至少包含：

- IndexTTS2 基础音色文件的内容 SHA-256，而不是易变的路径；
- 情绪类别；
- 模板版本和模板文本摘要；
- 规范化池情绪向量；
- IndexTTS2 完整 engine fingerprint；
- 输出规格。

具体尝试的缓存键在池族键基础上增加确定性种子。池元数据的 head 指向当前成功尝试，因此查找过程不会依赖尚未确定的“成功种子”。

因此：

- 两个角色使用相同音色文件时可以安全命中同一音频 blob；
- 音色文件内容、IndexTTS2 模型、运行配置、模板或输出规格变化后自动产生新键；
- GSV 模型配置不进入参考池键，因为它不参与 IndexTTS2 参考音频生成；
- 现有 content-addressed `artifact_blobs` 和 `cache_entries` 继续承担文件去重，不复制 WAV 数据。

增加持久化的 Director 池元数据，用于记录逻辑键、当前成功条目、模板、情绪类别、成功种子、质量结果、blob SHA、生成状态、失败信息、替代关系和时间戳。它不是第二套音频存储。

## 8. 生成、并发与重试

池采用按需生成，不在项目启动时预热“角色数 × 8”条音频。

1. 首个消费者原子地取得对应池族键的构建权并提交 IndexTTS2 durable job。
2. 同键的其他消费者等待该构建结果，不重复提交 GPU 推理。
3. 音频必须通过 3.0～10.0 秒检查及现有 VAD 质量检查；关闭 ASR 文本相似度评分不等于关闭 VAD。
4. 失败时使用预定义的确定性备用种子重试两次。
5. 当前情绪三次均失败时，改用同音色的平静池条目，并在生成项上记录 `degraded_from`。
6. 平静池也失败时，仅当前语句失败；其他生成项继续执行。
7. 用户主动重生成时增加池修订号，并由“池族键 + 修订号 + 尝试序号”推导一组新的确定性种子，保证操作不会只命中旧 WAV 缓存。
8. 服务中断后，持久化构建记录按现有 durable job 恢复策略恢复或明确标记为可重试，不永久停留在 building。

Director 当前按阶段串行生成参考，但池层仍必须以数据库唯一约束或等价原子协议去重，以便两个 Director 项目并发运行时也不会重复构建同一键。

## 9. 与现有版本系统的集成

参考池不得破坏“参考 WAV、实际朗读的中文文本、情绪参数和引擎指纹不可分离”的现有约束。

Director 生成项新增或等价持久化以下执行元数据：

- `reference_mode`: `independent` 或 `pooled`；
- `reference_pool_entry_id`；
- `reference_emotion_bucket`；
- `reference_degraded_from`，可空；
- 实际 `prompt_text`、绑定版本和 blob SHA 可通过池条目及 artifact version 追溯。

对于池模式：

1. Director 审核记录继续保存原 `ref_text_cn` 和原连续情绪向量。
2. materialized execution segment 或 reference job override 使用池模板、池规范化向量和池成功种子。
3. 为当前 segment 创建正常的、不可变的 reference artifact version，但允许它引用现有 content-addressed blob。
4. GSV durable job 从该 reference version 构造 `ReferenceBinding`；禁止从原短句 `ref_text_cn` 猜测 `prompt_text`。
5. GSV 的 `text`、语言、速度、停顿和目标种子仍取自原语句快照。

这样既能复用物理音频，又保持每个语句的版本绑定、导出和审计链完整。

## 10. WebUI 行为

Director 语句卡片显示以下之一：

- `独立参考`；
- `情绪池：惊讶`；
- `情绪池：平静`；
- `已降级：惊讶 → 平静`。

展开详情同时显示：

- 原始中文参考文本；
- 实际采用的池模板；
- 池情绪类别；
- 对应参考音频播放器和版本标识。

局部“重新生成参考音频”在池模式下创建一个新的池条目版本：

- 当前语句在新版本通过校验后切换到它；
- 新版本成为该逻辑池后续消费者的默认版本；
- 已完成的其他语句继续绑定旧的不可变 reference version；
- 失败时当前绑定不被清空。

用户将中文参考文本手动改成超过触发阈值的正常长度后，继续使用“独立参考”流程，不被短句池强制覆盖。

## 11. 错误与可观测性

错误响应和实时活动窗口应显示实际层级，不再把底层质量失败笼统包装成 `ENGINE_UNAVAILABLE`：

- 池构建时长失败；
- 池构建 VAD 失败；
- 第几次种子重试；
- 从何种情绪降级到平静；
- 最终使用的是缓存命中还是新生成；
- pool entry ID、reference job ID 和 utterance ID。

项目进度条继续按生成项统计。缓存构建等待应显示为“准备短句情绪参考”，而不是让用户误以为 LLM 或 GPU 没有工作。

## 12. 验收标准

### 单元测试

- Unicode 引号、全角/半角标点和空白规范化；
- 1、2、3 个有效字符以及中英混合文本的触发边界；
- 8 维情绪的唯一最高值、`0.15` 强度边界、`0.05` 领先边界、平静最高、全零、等值和接近并列；
- 缓存键包含所有失效因子且不包含 GSV profile；
- 池选择不修改原始 Director utterance 字段；
- 错误降级与底层错误码保真。

### CPU 集成测试

- “砰”“嗯。”“嗯？”直接使用池，不调用 LLM corrector；
- 较长文本修正预算耗尽后进入池；
- 同键并发只创建一个池构建任务；
- 不同基础音色不共享池条目；
- 相同基础音色可以共享 blob，但每个 segment 均有自己的 reference version；
- GSV `prompt_text` 与池音频 manifest 的文本完全一致；
- 原始对白、译文、原情绪向量、速度、停顿和目标种子保持不变；
- 服务重启后命中成功池；
- 情绪池失败后降级平静，平静失败时只失败当前语句；
- 局部重生成产生新池版本且不改写旧绑定。

### 真实 GPU 验收

- 至少两个角色、两种 IndexTTS2 基础音色；
- 中文目标及日语目标各覆盖“砰”“嗯。”“嗯？”；
- 所有池参考音频均处于 3.0～10.0 秒并通过 VAD；
- 短句不再出现 `REFERENCE_DURATION_INVALID`；
- GPT-SoVITS 实际输出可播放，角色音色无串用；
- 句级 ZIP 仍以审核后的中文原句命名，池模板不得进入导出文件名。

## 13. 实施边界

实施应优先复用现有 durable jobs、GPU 单并发队列、`cache_entries`、`artifact_blobs`、artifact versions、质量策略、Director 进度和实时活动通道。新增代码集中在短句分类、池元数据/服务、Director reference resolution、GSV reference binding 以及最小 WebUI 状态展示；不建立另一套推理队列或音频文件仓库。
