# 导演模式 LLM 实时输出窗设计

## 1. 目标

在导演模式中央工作区标题下方，将目前只有“正在工作/空闲”的 LLM 状态条升级为可滚动的实时输出窗，让用户无需离开导演模式即可确认剧本分析、角色归并和台词翻译是否仍在工作，并查看最近的模型响应。日志窗必须位于首屏主流程区域，不能藏在左侧长表单的独立滚动区内。

## 2. 范围

- 复用现有 `GET /api/v1/llm/activity`，不新增后端接口、数据库表或凭据边界。
- 只显示 `script_analysis`、`cast_reconciliation`、`script_translation` 三类导演事件；不混入章节规划、参考修正和连接测试。
- 展示事件时间、中文阶段名、状态消息和已有的脱敏 `content`。
- 活动中显示累计秒数；最近事件失败或重试时沿用现有红色、黄色样式。
- 日志区域有固定最大高度并纵向滚动。用户停留在底部时自动跟随新事件；用户向上阅读时不强制跳到底部。
- 页面刷新后，只要控制面未重启，仍可从现有内存活动日志恢复最近事件。控制面重启后的永久日志保存不属于本次范围。

## 3. 前端结构

新增 `director-llm-activity.js`，只负责纯数据转换：过滤导演事件、从同一 `operation_id` 的生命周期事件推导导演任务是否仍活动，以及生成状态文字。`director.js` 负责请求现有接口和 DOM 渲染；`index.html` 提供独立状态与日志节点；现有 `.llm-activity-*` 样式直接复用。

导演模式继续每 1.2 秒轮询一次活动接口。接口暂时不可用时保留最近事件并显示“连接异常”，恢复后自动继续更新。

## 4. 错误与隐私

- 接口错误不会阻断项目、角色或生成页面的其他刷新。
- 前端只渲染活动接口返回的 `message` 与 `content`，使用 `textContent`，不解释 HTML。
- API Key、Authorization 和完整 prompt 仍由现有后端活动日志边界负责过滤，本次不改变该边界。

## 5. 验收

1. 导演模式页面包含独立的 LLM 状态节点和可滚动日志节点。
2. 纯函数测试证明章节规划事件会被排除，三类导演事件会保留。
3. 多个并行导演 operation 能从生命周期事件正确推导活动/完成状态。
4. 导演脚本使用 `textContent` 渲染输出并保持接近底部时自动滚动。
5. `ruff`、`mypy`、JavaScript 语法检查和非 GPU 测试全部通过。
