# LLM 实时活动小窗设计

## 目标

在章节阶段进度条上方增加一个紧凑、只读、可滚动的 LLM 活动窗口，让用户能确认模型请求已经发出、仍在等待、发生重试、收到响应以及解析完成或失败。

## 现状

当前 OpenAI 兼容调用使用非流式 `POST /chat/completions`。HTTP 请求发出后到完整响应返回前没有 token 数据，WebUI 只能显示“正在规划分块”，无法区分请求仍在工作还是页面失去响应。

## 采用方案

保留已验证的非流式协议，增加轻量观测层，而不是切换到兼容性更不稳定的流式协议。

后端维护一个进程内、有界的 LLM 活动缓冲区：

- 最多保存最近 80 条事件；
- 每条输出最多保存 64 KiB，超出部分明确标记截断；
- 记录操作 ID、时间、操作类型、事件类型、可读消息和可选输出；
- 记录 `started`、`request_sent`、`retrying`、`response`、`completed`、`failed`；
- `active` 由尚未出现终态事件的操作集合派生；
- 仅存内存，服务重启后清空。

公开 `GET /api/v1/llm/activity`，返回当前 active 状态和事件快照。WebUI 每 750 ms 拉取一次；本地 loopback 请求开销很小，并避免再维护第二套 SSE 重连状态。

## 输出与隐私边界

- 展示模型返回的 `choices[0].message.content`，包括原始 JSON 字符串或对象。
- 展示解析后的完成摘要与失败码。
- 不记录或返回 Authorization、API Key、请求头、base URL、完整 prompt 或用户输入原文。
- 请求事件只显示模型名、操作类别、尝试次数和状态。
- 页面使用 `textContent` 构造条目，不把模型输出解释成 HTML。

## WebUI

小窗位于 `#chapter-progress` 正上方，包含：

- 标题“LLM 实时活动”；
- 状态点与“空闲 / 正在工作 / 连接异常”；
- 正在工作时基于 started 时间显示持续增长的等待秒数；
- 固定最大高度的滚动日志区；
- 用户位于底部时自动跟随新事件；用户向上滚动后不强行拉回底部；
- 无事件时显示“等待 LLM 请求”。

每条记录显示时间、操作标签、消息；模型响应内容使用等宽、自动换行的 `<pre>`。

## 错误处理

- LLM HTTP/校验失败：先保留已有 response 事件，再追加 failed 事件。
- 活动接口暂时不可用：窗口显示连接异常，章节主流程不受影响，下次轮询自动恢复。
- 假模型模式同样产生 started/completed，便于测试和演示。
- 页面隐藏时浏览器可能降低轮询频率；恢复可见后下一次轮询会取回缓冲区快照。

## 非目标

- 不展示模型内部思维过程或供应商不可见的信息。
- 不改成 token 流式生成。
- 不把活动日志写入 SQLite 或磁盘。
- 不把活动事件绑定为章节审计记录。

## 验收

1. LLM 请求等待期间窗口显示 active 和等待秒数。
2. 响应后窗口显示原始 JSON 输出并可滚动。
3. 重试和失败有明确条目。
4. API Key 和 Authorization 不出现在活动快照。
5. 缓冲区严格限制为 80 条，单条内容限制为 64 KiB。
6. WebUI 使用安全文本渲染，活动接口故障不影响章节功能。
7. 全量非 GPU 回归通过。
