# 导演模式角色复核恢复设计

## 问题与根因

历史版本只把 `role_id` 变更识别为角色结构修改；在角色复核阶段切换 `speak_enabled` 时，项目会被错误推进到 `translation_review`。拆分产生的新语句又会把 `role_confirmed` 重置为 `false`，最终形成“翻译校对阶段仍有待确认配音语句”的非法历史状态。前端只允许 `role_review` 阶段操作角色、配音、拆分和合并，因此用户无法恢复。

黄色边框表示 `role_confirmed=false`；“100%”是模型置信度，并不代表人工确认。

## 采用方案

- `role_review` 与 `translation_review` 都允许角色确认、角色选择、配音开关、角色管理、拆分和合并。
- 翻译校对阶段执行任一上述修改时，复用现有后端 `_touch_project(..., role_change=True)` 自动将项目退回 `role_review`。
- 退回后重新执行角色确认与翻译，避免继续使用与角色结构不一致的旧译文。
- 配音文本编辑仍只允许在 `role_review`，不扩大文本修改状态边界。
- 翻译校对阶段的可操作控件显示提示：修改后会返回角色复核并需要重新翻译。

## 验收标准

- 历史异常项目中的黄色语句可以直接点击“确认角色”。
- 翻译校对阶段可以选择角色、切换配音、拆分及合并。
- 任一结构修改完成后，项目状态变为 `role_review`。
- 当前黄色语句确认后边框恢复正常，角色复核控件继续可用。
- 全量非 GPU 测试、CI、真实 WebUI 验收通过。
