# 中文参考音频质量门简繁体规范化设计

日期：2026-08-11
状态：生产故障确认，进入实施

## 1. 生产证据

章节 `695971e5-91c8-488f-ace4-c3df4fc3a078` 的第三个参考任务生成了 5.61 秒音频，
VAD 检查全部通过。期望文本为简体中文，faster-whisper 返回了内容相同的繁体中文：

- 期望：`明明我应该很生气可被你这样托着我却一句话都说不出来`
- ASR：`明明我應該很生氣可被你這樣拖著我卻一句話都說不出來`

当前规范化只做 Unicode NFKC、大小写折叠和标点过滤，因此相似度被误算为 `0.56`，
低于 `0.60` 的质量阈值。

## 2. 决策

复用 OpenCC 官方 Python 3.11 Windows wheel，在字符过滤后将中文统一转换为简体，再交给
RapidFuzz。不能降低全局相似度阈值，因为那会放过真正的错读和漏读。

同时将 `QualityPolicy.normalizer_version` 从 `1` 升为 `2`，并把 OpenCC 版本写入真实质量
分析器的策略指纹，以便质量缓存自动失效。

## 3. 验收

1. 生产中的简繁体样例通过质量文本检查；
2. 非等价错字仍由 RapidFuzz 计入差异；
3. 现有短文本、时长、VAD 和阈值边界不改变；
4. 质量缓存使用新策略指纹，不复用旧结果；
5. 完整非 GPU 测试与 Windows CI 通过。
