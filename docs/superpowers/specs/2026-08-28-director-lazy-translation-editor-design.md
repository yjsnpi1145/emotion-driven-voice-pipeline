# 导演模式译文编辑器按需展开设计

## 问题

导演项目进入翻译校对阶段后，前端会为每个已勾选“配音”的语句立即创建目标语言文本、中文情绪参考、语速、停顿和八维情绪向量控件。长篇项目会同时渲染数百个完整表单，导致语句卡片全部展开，页面明显卡顿甚至无法继续操作。

## 方案比较

1. **按需创建折叠面板（采用）**：配音语句默认只显示紧凑摘要，用户展开某句时才创建该句表单；收起时卸载表单并通过现有草稿状态保留输入。它同时解决意外展开和 DOM 过载。
2. 只用关闭的 `<details>` 包裹现有表单：视觉上折叠，但所有控件仍会创建，无法解决性能问题。
3. 对整个语句时间线做虚拟列表：性能上限更高，但会显著扩大改动范围，并增加拖拽、多选和表单状态的复杂度。

## 交互设计

- 勾选“配音”只修改该语句是否参与后续配音，不自动展示完整译文表单。
- 翻译校对阶段的配音语句显示“展开编辑译文与情绪”折叠入口，默认关闭。
- 展开时才挂载现有译文、参考文本、语速、停顿、情绪向量及保存按钮。
- 收起时卸载表单；任何输入已通过 `dirtyTranslations` 保存为内存草稿，重新展开时恢复。
- 存在未保存草稿时，折叠摘要显示“有未保存修改”。
- 非配音语句不显示译文编辑入口；角色复核阶段仍只显示配音开关和角色编辑控件。

## 代码边界

- 新增一个无 DOM 依赖的懒挂载状态同步辅助模块，负责“关闭不挂载、首次展开挂载一次、收起卸载”的行为，便于 Node 单元测试。
- `director.js` 负责构建 `<details>` 容器，并复用现有 `translatedEditor()`。
- 新模块加入本地 WebUI 静态资源白名单，并添加 HTTP 合同测试，避免再次出现模块 404。
- CSS 只补充折叠摘要与展开区布局，不修改整体主题。

## 验收标准

- 翻译校对项目初次渲染时，配音语句存在折叠入口，但完整译文表单数量为 0。
- 展开一条语句后只创建 1 个完整译文表单；收起后恢复为 0。
- 收起再展开能恢复未保存草稿。
- 勾选“配音”后页面保持紧凑且可继续操作。
- 新模块 HTTP 返回 200，浏览器控制台无模块加载错误。
- Python、JavaScript、全量非 GPU 测试及 CI 通过。
