# 失败章节修复后续跑设计

## 目标

为失败或因重启而中断的章节增加“修复后继续章节”能力。用户先在现有分块工作台中修复失败分块，再从原章节继续生成；已经存在且仍有效的当前 GSV 版本不得重复推理。

## 方案选择

采用原章节原地断点续跑，而不是复制新章节或整章重跑。原地续跑可以继续使用现有分块、不可变版本、任务进度和最终导出地址，且不会制造重复章节历史。复制新章节会导致版本历史割裂；整章重跑会浪费已完成的 GPU 推理，因此不采用。

## 状态与并发

- 仅 `failed`、`interrupted` 章节可以续跑。
- `queued`、`running`、`succeeded`、`cancelled` 均返回 `CHAPTER_STATE_CONFLICT`。
- 状态转换必须通过 SQLite 条件更新原子完成：`failed|interrupted -> running`。转换同时清除旧错误和旧完成时间，并刷新开始时间。
- 同一章节的第二个并发续跑请求会因状态已经变为 `running` 而失败，不得启动第二个后台编排任务。
- 续跑继续使用章节快照中的参考音色路径、参考音色 SHA-256、模型配置 ID、导演计划和输出规格。参考音色缺失、是符号链接或摘要变化时拒绝续跑。

## 断点判定

章节按 ordinal 依次检查持久化进度：

1. `gsv_state=ready`：该分块已有仍匹配当前输入和当前参考版本的 GSV，直接跳过。
2. GSV 未就绪但 `reference_state=ready`：复用当前参考版本，只生成 GSV。
3. 参考未就绪且最新参考任务为 `failed|cancelled|interrupted`：把该分块视为尚未修好，拒绝续跑并返回分块 ordinal、segment ID 和 `action_required=regenerate_reference`。不得自动重复同一个已知失败参考任务。
4. 参考未就绪且最新参考任务仍为 `queued|running`：拒绝续跑并提示等待当前局部重生成结束，避免重复推理。
5. 参考任务显示成功但没有可用当前参考版本，或当前参考草稿与版本不匹配：拒绝续跑并提示重新生成参考音频。
6. 从未开始的后续分块（没有参考任务、没有参考版本）：继续使用原导演计划执行参考文本时长修正、参考生成和 GSV 生成。

每个新任务仍写入 `chapter_run_segments`，所以现有 progress API、SSE、刷新持久化和失败显示无需旁路状态。

## API

新增：

`POST /api/v1/chapters/{run_id}/resume`

成功返回 HTTP 202：

```json
{
  "run_id": "uuid",
  "request_id": "uuid",
  "status": "running",
  "status_url": "/api/v1/chapters/{run_id}"
}
```

不存在返回 404；状态冲突或分块未修好返回 409，正文沿用现有 `{ "error": PipelineError }` 契约。控制面停止接收工作时返回 503。

## WebUI

- 章节操作区增加“修复后继续章节”按钮。
- 仅当前章节为 `failed` 或 `interrupted` 时启用；其他状态禁用并通过 title 说明原因。
- 点击后调用续跑 API，成功后立即刷新章节和进度并继续使用现有 SSE。
- 失败提示必须保留后端给出的中文分块序号和错误码，用户可以据此选择该分块重新生成参考音频。
- 浏览器静态资源版本号升级，避免旧 `app.js` 缓存隐藏新按钮行为。

## 错误处理

- 续跑后台出现的 PipelineError 仍持久化到章节 `error`，章节重新进入 `failed`。
- 取消服务时保持现有取消语义。
- 不自动修改用户草稿、不自动激活旧历史版本、不自动降低质量阈值。
- 已完成分块的当前版本只读复用；最终成功后重新生成 `final.wav` 与 timeline。

## 验收

1. Store 测试证明失败/中断可原子恢复为 running，旧错误和完成时间被清除，其他状态拒绝。
2. 服务测试证明有效 GSV 被跳过、已修复参考只生成 GSV、从未开始的后续分块正常执行。
3. 服务/API 测试证明失败参考未修好时返回可操作的 409，且不会新增推理任务。
4. API 测试证明成功返回 202，重复续跑被拒绝。
5. WebUI 契约测试证明按钮、启用规则和请求路径存在。
6. 全量 CPU 测试、Ruff、Mypy 和 JavaScript 语法检查通过。
7. 在真实失败章节上先验证未修好时被阻止，再修复参考并续跑到完成或记录真实引擎仍存在的独立失败。
